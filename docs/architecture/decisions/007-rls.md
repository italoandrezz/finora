# ADR-007 — Avaliar PostgreSQL Row-Level Security

**Estado:** pendente de prova de conceito; não ativada. Data: 23/10/2026.

Contexto: schema compartilhado torna uma query sem filtro de tenant um risco importante.

Proposta a avaliar: RLS como segunda barreira, com identidade de aplicação sem superuser/BYPASSRLS nem propriedade das tabelas, contexto local à transação e migrations por papel separado. Ausência de contexto deve falhar fechado.

Alternativas: somente filtros obrigatórios + FKs compostas + testes (menos operação, depende mais de disciplina); schema/banco separados (isolamento operacional mais forte, maior custo de evolução).

Vantagens: defesa adicional contra omissão de filtro. Desvantagens: pool/contexto, manutenção, testes de papéis, efeitos em planos de consulta e riscos de falsa sensação de segurança. Owners e roles privilegiadas podem contornar políticas; constraints referenciais não são uma autorização de negócio.

Consequências: executar ISO-10 com os papéis reais, medir custo e aprovar antes de depender da proteção. Mesmo se aprovado, manter todas as FKs e filtros do [modelo multiempresa](../multi-tenancy.md). [Documentação PostgreSQL 17](https://www.postgresql.org/docs/17/ddl-rowsecurity.html).
